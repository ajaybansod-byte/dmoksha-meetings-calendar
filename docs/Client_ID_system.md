# Client ID system

Every customer gets one permanent **Client ID**, created by the database (not by any app), shared by the calendar,
staff portal, ERP and order form.

- Format: `DC-DI-A0001` … `DC-DI-A9999`, then `DC-DI-B0001` … (4 digits). Kiosk / Hometown customers: `DC-HT-A0001` …
- One customer = one mobile number (normalised to 10 digits). Same mobile → same Client ID everywhere.
- Generated by triggers on `designer_meetings`, `customer_orders`, `kiosk_quotes`, `estimates`, `customers`
  (functions `assign_client_id`, `next_client_id`, `format_client_id`, `norm_mobile_for_id`; counters in `client_id_counters`).
- Fake / placeholder mobiles (e.g. all same digit) are blocked from getting an ID (`client_id_blocked_mobiles`).
- Old DMC codes were retired; they are kept in `customers.legacy_dmc_code` for reference.
- Backfill on 2026-10-01 gave IDs to 526 existing customers (approved dry run: `backups/Client_ID_dry_run.xlsx`, not in git).

## For other apps (ERP, order form)

Never generate an ID in app code. Read `client_id` from the row after insert (the trigger fills it), and show it next
to the customer name wherever a customer appears.
